# Fish 报表：图鉴、新枪与首次收集成长点

Status: ready-for-agent
Implementation: completed
Date: 2026-10-28

## Problem Statement

策划希望通过调优报告判断玩家持续获得成长反馈的节奏。当前同源报表主要将摸鱼厅扩容、杠铃、摸鱼神器、两类重生、突破资助及部分系统开放计入成长时间点。正常图鉴完成、新枪获得及首次收集新鱼／新变异虽已有底层事实，却未完整进入成长图、次数和间隔统计。

因此，报告可能显示很长的“无成长”时段，但玩家在这段时间实际完成了图鉴、获得了新枪或新收集。本次补齐收集成长的展示和统计，使策划能据此评估成长密度。

## Solution

在现有同源成长时间图、每日／每周汇总与成长间隔指标中，新增四种标签：正常图鉴完成、新枪获得、新鱼种获得、新变异组合获得。保留现有成长项及独立事件明细。

以游戏实际解锁和永久拥有事实为准；普通捕获和鱼蛋实际孵化均可触发收集成长。新鱼种按鱼种身份判断，新变异按“鱼种＋非普通变异”组合判断。首次获得的鱼本身带变异时，一个收集事件可有两个标签，总成长次数只增加一次。

新枪按每把枪首次永久拥有计数，不把领取、拥有、装备分别重复计入成长。正常图鉴完成和随后获得枪是两个不同里程碑，可以各计一次。

## User Stories

1. As a 数值策划, I want 在成长图上看到正常图鉴完成, so that 我能判断收集目标达成的节奏。
2. As a 数值策划, I want 看到每把新枪首次获得的时间, so that 我能判断图鉴奖励是否及时兑现。
3. As a 数值策划, I want 图鉴完成和枪获得分别保留, so that 我能看到达成条件与实际获得奖励之间的等待。
4. As a 数值策划, I want 同一把枪的领取、拥有和装备不重复增加成长次数, so that 成长密度不会被同一份奖励放大。
5. As a 数值策划, I want 看到首次获得每种鱼的时点, so that 我能判断新鱼种出现的频率。
6. As a 数值策划, I want 看到每种鱼的每种新变异组合, so that 我能判断变异收集提供的长期目标。
7. As a 数值策划, I want 首次出现的变异鱼同时标出新鱼种和新变异, so that 我能理解这次获得的双重意义。
8. As a 数值策划, I want 这类双标签获得在总数中只计一次, so that 总成长次数仍代表独立成长事件。
9. As a 数值策划, I want 重复获得同种同变异鱼不新增成长, so that 普通重复掉落不会淹没有效收集反馈。
10. As a 数值策划, I want 卖鱼后重新获得仍尊重历史解锁, so that 背包变化不会伪造首次获得。
11. As a 数值策划, I want 普通捕获和鱼蛋孵化使用同一套首次判断, so that 不同获得途径不会各自重复计数。
12. As a 数值策划, I want 鱼蛋入包时不提前计作新鱼, so that 成长时间对应实际获得结果。
13. As a 数值策划, I want 每个成长点显示具体鱼种、变异或枪身份, so that 我能追溯是哪项内容带来成长。
14. As a 数值策划, I want 有可靠名称时展示名称且保留配置 ID, so that 我可以把报告与导表快照对应起来。
15. As a 数值策划, I want 新成长项进入每日和每周汇总, so that 我能同时看短期体验与长期节奏。
16. As a 数值策划, I want 首次等待、最长间隔和尾部等待使用更新后的成长集合, so that 指标与图中的点保持一致。
17. As a 数值策划, I want 分类标签计数与去重后的事件总数明确区分, so that 我不会误认为分类数之和必须等于总次数。
18. As a 数值策划, I want 继续看到原有系统成长项, so that 这次补充不会丢失原有分析能力。
19. As a 数值策划, I want 成长时点使用实际事件时间和累计在线时间, so that 离线等待不会被混入在线成长间隔。
20. As a 数值策划, I want 从 checkpoint 继续时不把已有鱼种、变异和枪当成新获得, so that 连续模拟和分段模拟结果一致。
21. As a 数值策划, I want 本段成长统计与生命周期首次事实清晰区分, so that 续跑报告不会重放此前成长。
22. As a 数值策划, I want 旧报告在证据充足时可重新生成这些成长点, so that 不必为已有事实重跑长模拟。
23. As a 数值策划, I want 旧数据缺失时明确显示未记录或无法判断, so that 我不会把缺失误认为零次成长。
24. As a 数值策划, I want 补充报告不改变随机结果、奖励、钱包和行为策略, so that 新旧数值运行仍可归因。

## Implementation Decisions

- **现有边界**：继续由 Lua 服务决定捕获、孵化、图鉴解锁及枪拥有；Python 只观察和生成报表，不实现第二套随机或奖励规则。
- **图鉴完成**：本次新增的图鉴完成点指现有正常图鉴奖励目标首次满足条件，使用稳定奖励身份去重。变异图鉴的永久枪强化沿用已有成长项；不额外发明另一套变异图鉴完成判定。
- **新枪获得**：使用永久拥有枪的事实，以枪 ID 为生命周期去重键。领取和首次装备继续保留独立明细，但不成为额外的新枪成长点。初始已拥有的枪仅作为起始状态，不在本段开始伪造获得时点。
- **首次鱼种**：以 Fish ID 为生命周期身份，不限制首次获得时的变异类型。不得将 Fish ID 当成表行号、稀有度或概率阈值。
- **首次变异组合**：以 Fish ID 和变异 ID 的组合为身份；“新变异”表示该鱼种的新非普通变异，而不是全局首次见到一种变异类型。普通变异身份以源契约为准，不通过展示名称猜测。
- **原始事实来源**：复用图鉴解锁观察中的组合身份和枪里程碑。首次解锁来自永久图鉴历史，不依赖现存背包，不依赖是否配置或领取单鱼奖励。没有奖励配置的合法收集仍可形成成长点。
- **双标签计数**：一个新解锁组合生成一个独立收集成长事件，可同时带“新鱼种”和“新变异组合”标签。事件总数、密度、时间间隔、日／周次数按事件身份去重；分类统计按标签计数，并说明标签数可能重叠。不得简单将同秒所有事件合并，不同鱼种或独立里程碑即使同秒发生也分别保留。
- **同批多组合**：同次观察若首次出现同一鱼种的多个组合，只能有一个“新鱼种”事实。优先使用可验证的源获得顺序；源记录不足以区分时，按稳定组合身份选取该标签的承载事件，标注为同批观察，不声称存在额外的先后精度。
- **展示契约**：成长行保留稳定事件身份、标签、鱼种／变异／枪或图鉴奖励身份、墙钟时间、累计在线时间。名称只从本次冻结输入或已保存的显示元数据取得；无名称时显示明确的 ID，不读取当前生产表替历史结果补名。
- **页面口径**：成长图标题和说明须覆盖系统、收集及突破资助，观察事件不应被统一描述为玩家主动“操作”。原有分类、每日／每周图、分类说明、悬停信息、总览相关计数及成长间隔应使用一致的成长集合。原有突破资助成功支付计次、隐藏境界指标的规则保持有效。
- **时间与精度**：使用现有源事件／观察时点，不从 300 秒状态采样插值推测获得时间。不提升当前观察的精度承诺；实际结算时间与观察时间有差异时，应保留其语义。离线孵化按照源实际结算与现有在线时间规则处理，不凭理论孵化截止时间提前生成获得事实。
- **恢复与起始状态**：在观察边界建立起始已解锁鱼种、组合及已拥有枪的基线；必要时增补观察元数据和 checkpoint 状态。续跑时在观察新变化前恢复基线，保留首次事实，重复回执与重复查询不新增成长。不把生命周期记录重新全部计入本段成长图。
- **兼容策略**：完整新玩家历史可从旧解锁事件安全推导首次鱼种；新变异组合及枪事实按现有证据回放。旧续跑缺少起始解锁基线或首次历史时，不把本段第一个同鱼种事件自动认作新鱼种。标明新增分类覆盖不完整；缺失不是零，不能由期末背包补造历史时间。
- **模块职责**：按必要程度调整同源观察及保存、行为产物、报表投影、视图模型和页面渲染。优先在现有报告入口完成聚合，不另建模拟器或报告服务。行为身份或产物契约变化时同步相关版本／摘要输入。
- **回归与文档**：更新受影响的项目说明、报表口径、Fish 技能及代码导航。前端有变化时按现有离线生产资产流程更新压缩产物，不引入外部网络依赖或 source map。

## Testing Decisions

- **主要验收入口**：沿用正式模拟服务，运行受控短场景，读取正式事件、行为产物、checkpoint 及生成后的 Web 报告数据；从外部结果验证事实和计数，不针对内部函数调用次数或实现结构写测试。
- **报告入口补测**：沿用现有静态报告生成入口构造边界产物，验证标签、总数、每日／每周归属、身份显示和缺失提示。避免为每个内部转换层重复写相同测试。
- **既有先例**：同源图鉴回归已通过正式运行验证解锁先于领奖；枪回归已有完成／领取／拥有／装备里程碑；鱼蛋及联合恢复回归已有具体鱼实例与连续／恢复等价性；报表回归已有日／周统计、在线时间和缺失指标契约。扩展这些现有入口，不新增测试专用业务 API。
- **基础收集序列**：普通 A 首次获得→普通 A 重复→变异 A 首次→相同变异 A 重复→另一变异 A。期望 3 个独立收集成长事件，1 个新鱼种标签、2 个新变异标签。
- **首次即变异**：首次获得变异 B 产生 1 个事件、2 个标签；随后获得普通 B 不新增本次定义的成长点；再次获得该变异 B 也不新增。已有具体组合解锁明细仍保留。
- **批量与同秒**：同批多个实例、同鱼种不同组合、不同鱼种同秒、图鉴完成与枪获得同秒均保留正确的身份去重边界，结果排序可复现。
- **获得来源**：捕获后再孵化相同组合不重复；孵化新组合会触发成长；蛋入包、未孵化、鱼包满阻塞均不提前触发。卖鱼后重新获得不触发首次。
- **图鉴与枪链**：验证正常图鉴完成时点与领取之间可存在等待；每把枪永久拥有只计一次；装备和重复领取不追加新枪成长；枪强化仍按原规则显示；有解锁而无单鱼奖励配置也能统计收集。
- **时间统计**：新成长项真实缩短对应空窗；日／周事件数与总数可核平；多标签数允许大于事件数；离线时长不增加在线成长间隔，边界时点不能在相邻时段重复统计。
- **checkpoint 等价性**：在首次解锁前后、图鉴完成与领枪之间、孵化前后截断恢复。拼接本段事件后，首次身份、获得时点和成长总数应与连续运行一致；本段首次不能覆盖生命周期首次。
- **历史兼容**：完整旧事件重生成可恢复可证明的成长；旧续跑缺初始状态时显示覆盖限制，不伪造新鱼种；缺少名称、无新事件、重复事实等均有明确稳定输出。
- **观察无副作用**：同输入、种子和策略下，增补观察前后源捕获／孵化结果、奖励和钱包终值一致；展示变化不改变源结算。
- **执行范围**：实施后运行相关报告、图鉴、枪、蛋和恢复回归及正式 smoke。源仓库或 Lua 缺失造成 skipped 不算集成通过；不默认运行全部 1／7／30 天长场景。页面资产需验证中文分类、多标签提示与悬停身份展示。
- **测试边界核对**：用户已确认“符合，按现有入口验收”。采用上述正式运行／checkpoint 续跑与报告生成入口，不额外要求实际浏览器交互验收。

## Out of Scope

- 修改生产 Excel、Luban 导表、掉落概率、图鉴要求、奖励数值或系统开放门槛。
- 调整玩家策略、动作耗时、在线窗口、鱼潮固定五蛋近似或枪伤害收益模型。
- 将单鱼升级、每次训练、重复捕获、蛋入包或一般领奖全部加入成长点。
- 新增摸鱼厅阵容收益提升、成长前后倍率分析等尚未选择的建议。
- 扩展神兽获取与收益联动，或新增当前源宿主未覆盖的游戏系统。
- UE 碰撞、原生武器、网络复制、多人争夺或真机验收。
- 修改或恢复旧 Python Fish 项目、清理运行历史，以及改动本次范围外的工作区内容。
- GameBalancer 构建、发布、推送或替换已安装工具；本地实现不等于已交付包更新。
