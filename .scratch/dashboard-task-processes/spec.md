# Dashboard 每次任务使用独立 Python 进程

Status: ready-for-agent

创建日期：2026-10-28

范围：源码开发环境的 Dashboard。实施与验收结果见 [verification.md](verification.md)。

## Problem Statement

开发者更新 Python 模拟策略、引擎适配或报告生成逻辑后，希望直接在 Dashboard 再次执行任务，获得基于当前代码的新结果。目前 Dashboard 在常驻 Python 进程内启动后台线程，调用已经导入的工作流和引擎模块。磁盘源码更新不会自动替换这些对象，因此重复运行可能继续使用旧逻辑。

已有服务重启入口可以重新加载代码，但会影响所有项目和标签页，也将“更新模拟后重新运行”变成了额外的运维操作。用户已确认采用每次任务启动独立 Python 进程的方案，使网页持续可用、后续任务使用最新代码。

Fish 的 Lua 宿主已经使用独立进程并冻结源模块与所选导表；本次问题主要发生在外层 Python 工作流、策略、适配和报告生成代码。正式运行仍须遵守既有定义：模拟与所需产物、调优报告均完成才算成功，报告失败不能显示整次运行成功。

## Solution

Dashboard 保持常驻，负责项目选择、请求校验、任务准入、状态展示和报告访问。每次需要执行模型逻辑的任务启动全新的 Python 解释器，在该进程内创建当前工作流、读取输入、执行任务并保存结果，完成后退出。下一次任务重新加载当前代码，不复用上一任务的解释器或模块对象。

用户仍使用现有场景下拉框和执行按钮。运行中可以刷新页面、查看状态、切换项目；更新代码后再次提交即可生效。启动失败、代码错误、运行失败和报告失败均有可见结果，失败后可以修正代码并重新提交，不要求重启网页服务。

服务重启入口继续保留，用于 Dashboard 自身页面、路由或进程调度实现的更新。已生成的静态报告不会因源码更新或页面刷新自动变化，仍须明确重新生成；本次不新增报告重生成按钮。

## User Stories

1. As a 模拟开发者, I want 修改 Python 模拟逻辑后直接再次运行, so that 无需重启 Dashboard 就能验证当前代码。
2. As a 模拟开发者, I want 连续两次任务各自加载代码, so that 上一次导入的模块不会污染下一次结果。
3. As a 模拟开发者, I want 被调用的依赖模块更新也在下一次任务生效, so that 不只顶层任务入口得到更新。
4. As a 模拟开发者, I want 连续快速保存源码后仍使用当前内容, so that 不因旧字节码缓存误以为修改没有生效。
5. As a 报告开发者, I want 新任务使用当前报告生成逻辑, so that 修改展示投影后可以直接验证新报告。
6. As a 报告使用者, I want 已有静态报告保持原有内容直到明确重生成, so that 历史产物不会在查看时被悄悄改写。
7. As a 模拟开发者, I want 已运行任务不被后续提交或主动热重载替换, so that 修改代码不会触发正在执行的模拟重跑。
8. As a Dashboard 使用者, I want 提交后立即看到任务受理和运行状态, so that 长时间计算不会表现为网页卡死。
9. As a Dashboard 使用者, I want 运行时仍能查看耗时、历史和诊断, so that 可以判断任务是否在执行及其结果。
10. As a Dashboard 使用者, I want 刷新页面或关闭标签页不取消任务, so that 浏览操作不会丢失已经提交的工作。
11. As a 多项目使用者, I want 切换项目后任务仍归属原项目, so that 模拟结果、报告和错误不会出现在另一个项目下。
12. As a 多项目使用者, I want 不同项目沿用既有独立执行能力, so that 一个项目的长任务不会把全部项目锁成单队列。
13. As a Dashboard 使用者, I want 同一项目的重复提交继续被拒绝, so that 双击或多标签操作不会重复启动模拟。
14. As a Dashboard 使用者, I want 场景继续从当前项目配置选择, so that 不会退回手填场景或错误的示例项目。
15. As a authoring 项目使用者, I want 独立进程沿用 authoring 的锁和输入准备流程, so that 不会跳过事务恢复、临时导出和一致性检查。
16. As a 配置项目使用者, I want 指定的配置、导表与运行目录原样传递, so that 新进程不会使用另一套默认输入或历史根。
17. As a Fish 模拟使用者, I want 保留 Lua 源码和导表冻结以及 checkpoint 检查, so that 新的执行方式不改变规则、恢复语义和归因边界。
18. As a 分析功能使用者, I want 分析任务也加载当前 Python 逻辑, so that 同一网页中的执行入口不会一部分新、一部分旧。
19. As a 模型维护者, I want 初次检查、手动刷新和任务完成后的检查使用当前模型逻辑, so that 旧就绪检查不会错误阻止或描述新运行。
20. As a Dashboard 使用者, I want 状态轮询只读取已缓存结果, so that 每秒查询不会重复启动解释器和模型检查。
21. As a 模拟开发者, I want Python 启动或导入失败时看到明确错误, so that 语法错误不会表现为无限运行或服务失联。
22. As a 模拟开发者, I want 工作进程异常退出后任务变为可识别的失败, so that 可以检查证据并在修复后继续使用 Dashboard。
23. As a 报告开发者, I want 报告生成失败时保留已完成的模拟产物, so that 可以定位报告问题而不用丢弃模拟数据。
24. As a Dashboard 使用者, I want 失败后不会自动重试模拟, so that 不会产生未经请求的重复运行和报告。
25. As a Dashboard 使用者, I want 已保存的运行历史、诊断和报告链接继续可用, so that 进程隔离改造不改变日常查阅方式。
26. As a Windows 使用者, I want 后台任务不弹出额外控制台窗口, so that 每次运行都不会干扰桌面操作。
27. As a Windows 使用者, I want 带空格和中文的项目目录可正常执行, so that 不必为进程启动重新安排目录。
28. As a Dashboard 维护者, I want 工作进程和其 Lua 子进程在受控结束时得到回收, so that 失败任务不会留下持续占用资源的后台计算。
29. As a Dashboard 使用者, I want 有任务时继续禁止重启服务或清理该项目历史, so that 不会破坏仍在写入的运行。
30. As a Dashboard 维护者, I want 重启按钮保留给服务自身更新, so that 页面或调度实现变更后仍有恢复入口。
31. As a 项目所有者, I want 此改动只影响开发 Dashboard, so that 执行工具包的源码隔离、发布和调优工作台边界保持不变。

## Implementation Decisions

### 执行范围与职责

- 保留现有网页操作与项目身份，不引入让浏览器指定任意 Python 文件、模块、可执行程序或 shell 命令的能力。新增工作进程只接受服务端允许的固定操作。
- 正式模拟入口及其 smoke 场景运行、分析任务、模型就绪检查和配置校验使用新的解释器进程。模拟的输入准备、引擎执行、checkpoint、模拟产物、报告和正式运行终态均位于同一任务的工作流生命周期内。
- 首次项目检查、手动刷新、任务完成后的自动检查使用同一执行边界。模型检查依然是检查，不额外登记正式运行；连续刷新按现有逻辑合并，防止并发创建检查进程。
- 历史列举、静态报告读取、任务状态读取、项目切换和页面渲染继续由 Dashboard 服务承担。历史删除和清空沿用现有服务接口、确认摘要和任务互斥，不以本次改造重写其事务与文件删除规则。
- 把任务进程执行与结果接收封装在一个供 Dashboard 使用的高层执行组件中。Dashboard 不再持有用于实际模拟、报告生成或就绪检查的长期引擎实例，也不向工作进程传递已加载的模型、适配器或工作流对象。
- 工作进程重新创建既有 WorkflowService／AuthoringService，继续进入 FormalRunExecutor。不得在进程入口复制另一套加载、模拟、写报告和登记状态的业务流程。分析任务保留自己的现有状态语义，不强行套用正式运行的成功定义。

### 启动和代码更新

- 每项计算任务创建新的解释器，不使用复用解释器的进程池，不在 Dashboard 中逐模块热重载。负责等待工作进程的后台线程可以保留，但不能承载模拟或模型检查逻辑。
- 使用服务对应的 Python 环境，明确传递项目身份、项目根、输入模式、配置、导表、实际历史写入根、操作及场景等必要上下文。相对路径的解析结果必须与原入口一致；子进程不得依赖当前浏览器选择或碰巧正确的工作目录。
- 使用参数列表或结构化输入传递数据，不拼接 shell 命令。Windows 后台创建进程不弹出可见窗口，并保留标准输出和错误证据。
- “使用最新代码”指在源码修改保存完成后提交的新任务加载当前源码及依赖；不能仅依赖进程 PID 变化证明成立。必须覆盖快速修改以及旧字节码存在的情形，具体缓存处理封装在开发任务启动边界。
- 不对正在运行的任务实施主动模块重载或自动重跑。已有 Lua／导表冻结、输入变更检测和 checkpoint 身份检查继续生效。本次不承诺整个 Python 源码树在任意并发编辑下具备原子快照，也不把运行中从磁盘重新计算的摘要冒充实际执行代码身份。
- Dashboard 自身代码、工作进程协议或启动组件发生不兼容更新时，仍可能需要服务重启。新旧协议不兼容应明确报错，不能静默回退到旧的进程内执行。

### 任务请求和完成回执

- 进程边界采用显式可序列化请求与结构化结果。请求至少绑定内部任务标识、操作和项目上下文；结果返回对应标识、业务状态、消息以及实际存在的运行／报告／诊断关联信息。
- 控制结果与普通日志分离，允许第三方库输出额外日志，不把任意一行标准输出当成成功结果。及时消费或重定向输出，避免输出管道填满导致任务阻塞；展示和传输的日志须有界。
- 进程退出码、结构化结果和已持久化运行终态共同用于判断结果。仅退出码为零、仅收到结果或仅存在报告文件，都不能单独证明正式运行成功。
- 保留 authoring 和配置项目的登记时点差异，不为方便通信提前伪造正式运行。运行登记后必须使监督方能够关联本次任务的运行身份，以便处理登记后崩溃；登记前失败保存任务级诊断，不创建不存在的成功记录。
- 正常完成后优先使用既有工作流保存的业务结果。收到结果但进程尚未结束时不提前释放执行保护。迟到结果必须核对任务身份，不能覆盖后续任务状态。
- 工作进程启动失败、导入失败、协议不匹配、结果缺失或损坏、非预期退出均产生明确失败，附带可获得的退出信息及诊断。若本次运行已经登记且仍为运行中，仅更新可确认属于该任务的记录；不得扫描并批量改写其他运行。
- 若磁盘已经保存合法终态但结果回传失败，保留已保存终态，单独说明回传异常；若无法安全核实或保存终态，页面显示失败／状态无法确认及其原因，不无限显示正常运行，也不伪造完成时间。
- 不自动重试失败任务，不把正常的长时间模拟当作通信超时强行结束。进程故障处理完成后，用户可以重新提交；历史仍需保留此前尝试及可用诊断。

### 并发、状态与服务生命周期

- 保留项目级互斥。保护范围覆盖任务启动、实际工作、产物提交、进程退出和结果归并；同一项目的重复计算提交继续被拒绝，不因一次 Python 调用返回就提前解锁。
- 不新增全局串行任务队列或提高既有并发上限。项目之间继续隔离，现有项目锁负责跨入口的一致性；浏览器切换不取消、不迁移任务。
- 提交保持快速响应；任务状态、耗时、诊断与报告入口继续通过现有项目限定接口提供。轮询不触发模型检查，也不重复启动进程。
- 模型检查的耗时工作移出 Web 服务，但检查结果仍缓存。页面刷新不得因为父进程缓存的旧检查逻辑而否定已经成功完成的新任务。
- 用户通过服务重启入口操作时，只要任一项目仍在计算或模型检查就拒绝重启。历史删除／清空继续遵守该项目的任务保护。
- 受控退出、任务进程失败和启动失败路径回收本次任务拥有的进程及相关资源，包括它启动的 Lua 宿主；Windows 必须实测，不能只终止解释器启动包装进程而遗留实际计算进程。不终止身份无法确认的其他进程。
- 浏览器刷新、断开或关闭标签页不视为取消请求。服务被操作系统强杀后的自动接管、继续计算或重放不在本次承诺内；后续读取残留记录不得假定成功。

### 兼容与交付

- 保持运行目录、已有报告 URL、报告面板、历史筛选、场景选择和跨项目路由兼容。自定义历史根及兼容历史读取规则继续由注册表统一处理。
- 保留仅本机监听、Host／Origin／CSRF 校验及报告文件路径限制。任务内部协议不成为可绕过网页校验的公开远程执行接口。
- 不改变游戏经济规则、玩家行为策略、采样口径或 checkpoint 格式；引擎结果应与同版本代码通过既有入口运行的结果一致。
- 本次仅修改开发 Dashboard 的执行方式。执行工具包和调优工作台不自动采用开发工作进程，不扩大发布白名单，不引入源码交付；遵守既有两项分发与源码隔离 ADR。
- 实施完成后同步代码导览与相关开发说明，解释哪些任务自动加载代码、哪些服务更新需要重启，以及静态历史报告的更新方式。若 Fish 的操作指引或代码导航受影响，再同步其项目技能，不能将规格中的未来行为写成已经实装。

## Testing Decisions

### 主要测试边界

优先沿用 Dashboard 现有的 HTTP 提交 → 任务状态 → 磁盘运行记录和产物这一条高层测试边界。通过真实本地服务、临时项目和真实任务子进程验证用户可观察行为；断言任务结果和文件内容，不以线程数量、内部调用次数或出现新 PID 代替功能验收。

仅在解释器无法启动、控制结果损坏等难以稳定制造的故障上，通过统一任务执行组件的启动边界注入故障。复用正式运行已有的引擎／报告写入替换点验证业务失败，不给每一层新增一套测试接口。

用户已确认上述测试边界：“符合，按此边界验收”。“ready-for-agent”表示规格已按 to-spec 发布并可进入实施，不代表实现已经通过验收。

### 必须覆盖的可观察行为

1. **真实源码更新**：启动一次 Dashboard，完成任务 A；修改隔离测试运行环境中的模拟 Python 模块及其依赖，再提交 B。B 的产物反映修改，A 的产物不变，Dashboard 地址与服务实例保持不变，全程不调用服务重启。
2. **字节码与连续保存**：预先产生字节码缓存，覆盖短时间内同尺寸源码变更；B 必须反映当前源码。不得只靠修改测试数据或伪造回执证明代码更新。
3. **报告更新**：服务持续运行期间更新隔离环境中的报告生成逻辑，后续任务生成新展示；已有报告不被查看、刷新或任务切换改写。
4. **就绪检查更新**：更新检查相关模块后执行手动刷新及后续运行；检查使用新逻辑。初次检查、任务完成后的检查也走同一边界，轮询不会重复运行检查。
5. **错误后修复**：在启动后的隔离环境中引入导入／语法错误，新任务明确失败；修复后无需服务重启即可成功提交和完成下一任务。
6. **运行失败归因**：模拟失败和报告失败分别保留正确阶段与诊断。报告失败保留模拟产物，历史记为失败；进程正常退出不覆盖业务失败。
7. **进程和通信故障**：覆盖启动失败、登记前退出、登记后异常退出、结果缺失／损坏／不匹配、保存终态后回传失败；不无限运行、不自动重试、不改写其他任务记录，下一次提交可用。
8. **输出与长任务**：输出大量普通日志和错误日志时不因管道阻塞卡死；慢任务期间主页、状态和报告读取保持响应，耗时持续可见，不设未经请求的模拟时间上限。
9. **输入与历史一致**：覆盖 authoring 与配置项目、默认与自定义历史根、显式配置／导表覆盖、中文及空格路径；运行清单中的输入与网页选定项目一致，没有回落到示例项目。
10. **并发与导航**：同项目双击／多标签提交被拒绝；项目 A 执行时切换 B 不串结果，B 沿用原有独立任务能力；刷新或关闭浏览器标签页不取消任务。
11. **执行中的代码修改**：任务 A 已加载的测试逻辑继续完成，保存修改后提交的 B 使用新逻辑，不通过重启 A、修改 A 产物或父进程热重载实现。
12. **重启与清理保护**：任务准备、执行、报告写入和结果归并期间拒绝服务重启及相应历史清理；任务完成后可执行原有操作，报告和历史仍可读取。
13. **资源收尾**：在真实 Windows 环境确认受控退出与异常路径不会遗留测试 Python／Lua 进程、持有管道或测试目录；启动窗口不可见，日志保留。
14. **既有语义**：保留分析任务既有业务状态、正式运行成功定义、诊断主次错误顺序、项目锁及输入快照行为。必要时运行正式运行的既有回归，不重写引擎计算断言。
15. **安全与界面**：无效 CSRF、Host、Origin 和越界文件请求仍被拒绝；网页中不能提交任意脚本命令。真实浏览器验证受理、失败后再运行、报告打开和项目切换。

### 既有测试基础与验证分层

- 复用 Dashboard 的慢任务立即响应、失败后继续提交、慢模型检查不阻塞读取测试模式。
- 复用多项目任务、凭证和报告隔离测试，以及历史清理的摘要确认与互斥测试。
- 复用现有服务重启的真实进程测试设施，但新增“服务不重启且执行内容更新”的验收，不能把整服务重启成功当成本功能完成。
- 复用正式运行的报告失败、诊断失败和终态写入失败测试，保留服务层权威的结果含义。
- 自动化主验收使用临时测试项目和隔离代码副本，不编辑生产脚本或生产导表来制造故障。无外部数据的 Generic 场景覆盖完整链；Fish 只在实际 Lua 和源输入可用时做正式 smoke，并单独记录环境与结果，不默认启动长周期模拟。
- 浏览器证据、进程集成测试、正式运行回归及外部 Fish 验证分别报告。访问受限或环境缺失时明确记录未验收，不能用 mock 通过替代真实边界证据。

## Out of Scope

- 改写 Fish 或其他引擎的经济公式、模拟策略、报表指标及采样规则。
- 运行期间热替换 Python 模块、自动重跑任务、持久工作进程池、远程队列或分布式调度。
- 新增用户取消／暂停／排队界面、断线自动重放、服务强杀后的任务自动接管。
- 整个 Python 代码树和环境的版本化打包或任意并发源码编辑下的原子快照。
- 自动重生成历史报告、新增网页报告重生成入口、修改历史清理语义。
- 将 Dashboard 页面与路由代码也改为每个请求动态加载，或删除已有服务重启入口。
- 将开发任务进程加入执行工具包、修改调优工作台、构建或发布 GameBalancer。
- Git 提交、推送、发布，以及清理当前工作区的其他未提交修改。
