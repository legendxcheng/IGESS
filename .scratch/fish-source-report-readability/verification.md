# Fish 同源报告可读性回归

日期：2026-09-24。

## 复现与根因

用户报告同源 Lua 后端的报表可读性明显下降。对比旧 30 天报告与同源运行 `20260924T065413912580Z-month_1_growth`，后者的 `fish_progression.available=false`，核心与成长 profiles 为空；旧报告为 true。

报表加载器仅读取旧 `luck_progression.json` / `behavior_progression.json`，上一轮迁移只给新 `source_progression.json` / `source_behavior.json` 增加了产物链接。页面仍按旧事件名与字段统计，导致购买和重生错误地显示为零、鱼投资面板消失。现有成功验收检查了产物文件和链接，却没有检查这些用户可见面板。

同源事件中带有完整 JSON 回执，页面将其再次全量内嵌，30 天 HTML 达 18,523,612 字节。这些长回执没有变成可读分析，反而增加页面体积和事件噪声。

另一个独立限制是旧 30 天运行只有 31 个状态采样点。报告适配可以恢复这些点，不能据此伪造 5 分钟在线毛收入、真实峰值、精确突破完成时点或最长停滞。

## 修复

- 加载器读取同源产物，并把缺失产物加入缺失清单。
- 新增纯报告投影，读取已保存的源状态与交易回执；不重算游戏规则或修改业务存档。
- 恢复力量、双 Luck、钱包与待领取收入、金币投资、杠铃购买时点，以及按周／按日的成长操作图。采用实际 go_online/go_offline 记录累计在线时长。
- 将突破资助与实际突破完成区分；26 次非立即突破在图中标为“突破资助（非完成）”。成长操作统计包含资助，不能当成已完成永久成长次数。
- 缺失 Luck 保留断点，峰值明确标为采样峰值；没有证据的毛产出、升级增收和停滞不填零。
- 同源总览只显示适用统计：完整投掷、鱼雷/杠铃购买、重生、拒绝与最终余额。缺少记录的通用回本/诊断板块不再显示误导性零值。
- 页面默认显示成长操作与拒绝，完整投掷合并计数；全量回执仍在原始 events.json，可通过相对下载链接访问。
- 同步源码版和压缩版前端，补齐中文标签；模拟时长、在线时长、操作间隔采用天／小时／分钟显示。
