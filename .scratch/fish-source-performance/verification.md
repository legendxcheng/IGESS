# Fish 同源模拟性能优化（2026-09-25）

延续 [性能票据](../fish-source-runtime/issues/04-long-run-migration-and-performance.md)，使用源执行器会话接口和 IGESS 正式工作流验证。数值表、导出 JSON、策略、采样周期与业务服务未改动。

## 定位证据

命令：`.venv/Scripts/python.exe .scratch/fish-source-performance/timed_simulation.py day_1_growth baseline-profile`。

1 天真实场景共 2206 次请求，其中 `query` 985 次、`advance` 356 次、`query_actions` 245 次。Python 侧请求累计约 10.41 秒，其中状态查询 6.17 秒、推进 1.87 秒、行动报价 0.49 秒；这些是含通信的往返时间，不能称为纯 Lua CPU 时间。

独立 Lua 指令采样进一步定位到背包查询的全鱼列表数值计算（`FishInventoryQuery` / `FishEconomyRules` / `BigNumber`）。带采样的运行中 `query` 内部约 9.65 秒，全部响应 JSON 编码约 0.66 秒、输出约 8.66 MB。探针会增加耗时，这些结果仅用于归因，不用于计算优化倍率。探针与旧宿主副本保存在 `debug/`，不进入生产执行器。

启动冻结约 4.0–4.3 秒；Python profile 中复制本身约 0.43 秒，三轮源码校验合计 3342 次 `read_bytes` 约 3.92 秒。主要可消除开销是立即重新打开新复制文件，不对防病毒软件等外部因素做已证实归因。

## 改动

- `E:/fish-oasis/simulation/Host.lua`：会话内缓存默认背包投影和行动报价。键覆盖完整鱼列表及鱼厅等级；只保存原服务/原报价函数的结果，不重写经济公式。返回独立副本并填入当前 revision。升级、出售、摆放、换位、新鱼和鱼厅变化会失效；缓存不跨会话、不序列化到 checkpoint。默认背包投影依赖依据源 `PlayerInventory/QueryContract.lua`，若该契约新增输入，须同步扩展失效键。
- `src/igess/fish_source_runtime.py`：复制输入时复用实际写入的字节计算哈希，避免复制后再次读取上千文件。原有路径排序、哈希字节格式、运行前身份检查和隔离目录保持。临时增加约一个输入快照的内存占用（当前不足 8 MB），函数返回后释放。
- 没有减少查询次数、采样次数或业务操作；保留每累计在线五分钟、上下线、领取及重生前后采样，保留独立资源余额图。

## 尚存开销与边界

当前仍使用完整生产服务投影及精确 BigNumber 运算；查询和交易结算仍有成本。不是把 Lua 换成 Lua 就能自动提速：此前同源宿主已是常驻 Lua 进程。本次不改变业务语义，也不承诺秒级完成 30 天。

旧 Python 后端策略不同，不能用于计算此次加速倍率。默认后端迁移、周期性中途 checkpoint 和执行工具包发布不在本次改动范围内。
