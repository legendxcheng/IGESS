## 实际改动

源模拟新增 `SnapshotScope`，Host 通过既有 ArchiveService 依赖注入，将摸鱼厅、库存、杠铃、神器、寻宝兽、重生、离线奖励、枪和图鉴接入单次完整 Query 的独立快照。状态按会话、coroutine 和查询生命周期隔离；嵌套查询建立新作用域，正常返回或抛错均清理。写操作、动作报价及独立查询继续转发原存档服务。

枪查询原本会删除 combat 投影中的私有 acquisitions；它现在获得独立 combat 分支，避免修改共享快照。原源服务继续负责投影与合法性。不同服务的 ID、规则和时间校验选项并不等价，因此没有合并或跳过这些校验，也没有全局替换 ArchiveService / Schema 行为。

交付内容为五个模拟 Lua 模块、一个专项测试及相关说明。未修改生产数值、源玩法服务、随机链、推进算法、Python 业务逻辑或协议；未提交、推送或发布 GameBalancer。源 Query 和 README 在开始前已有的其他改动保留；复制交付前逐文件检查其仍与冻结基线一致。

- 每组先计算自身减少比例，再取中位数：**4.34%**。这是配对变化的统计，与两侧耗时中位数之比是不同口径，不能互换。
- 基线范围 206.089–225.862 秒；候选范围 197.977–214.945 秒。
- 两组 Day1：19.447→18.430、18.728→18.065 秒；两侧中位数 19.088→18.248 秒，减少 **4.40%**。

判断：减少复制有直接调用证据，四组整周三组更快，补充的反向次序也显示改善，且两组 Day1 均改善，保留这个范围较小的候选。整周收益较小，并受背景负载与顺序漂移影响；不保证每次运行都更快，不将 4.34% 当作两侧耗时中位数降幅，也不承诺稳定达到某个百分比。
