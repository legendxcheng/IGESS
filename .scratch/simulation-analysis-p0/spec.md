# IGESS P0：运行查询、领域指标与目标对照接口

Status: ready-for-agent
Implementation: completed
Date: 2026-10-29

## Problem Statement

数值策划与 fish_sim 已能通过正式运行得到可归因的模拟产物和调优报告，但分析一次结果仍需要自行定位运行目录、打开多个文件、理解领域统计口径，再手动对照目标规划。后续数值模拟项目也会重复实现这些工作。

当前公共比较主要提取期末资源、购买、解锁、重生和回本指标。Fish 报告中的成长分类、收集双标签、自然日分布和在线成长空档尚未成为稳定的公共指标接口。缺少统一协议时，调用者容易将缺失数据当成零，将续跑本段事件当成生命周期事实，或用当前生产表解释旧运行。

用户确认先实现 P0：RunQuery、MetricProvider、TargetEvaluator。本规格定义这一批实现，不将后续实验扫描、跨运行比较或自动调参混入交付。

## Solution

提供面向 Agent 和本地开发工具的只读分析入口：按项目和运行身份查询历史，发现并提取该引擎支持的指标，再对照显式传入、带版本的目标定义，返回结构化结果及人可读的对照表。

分析使用已有运行产物及冻结元数据，不自动启动模拟、执行模型就绪探测、读取当前游戏生产表或修改源表。每个指标和目标结果都说明单位、时间基准、覆盖范围及证据，明确区分真实零值、未记录、未达到与不适用。

首批支持 Generic 的公共指标和 Fish Source 的成长分析。未来项目通过注册指标提供者接入，同一查询和评估协议继续可用。

## User Stories

1. As a 数值策划, I want 按项目查询正式运行, so that 我不会误用其他项目的报告。
2. As a fish_sim 调用者, I want 按场景、状态和引擎筛选历史, so that 我能定位用户指定的一轮结果。
3. As a fish_sim 调用者, I want 通过运行 ID 获取详情, so that 我不用猜测目录布局。
4. As a 数值策划, I want 区分正式运行与自动 smoke, so that 我不会把就绪探测当成长期成长结果。
5. As a 调用者, I want 同一 ID 的新旧历史副本沿用已有优先级, so that 查询不会重复或跳回旧报告。
6. As a 数值策划, I want 看到状态、实际执行耗时和报告位置, so that 我能判断该次运行是否完成。
7. As a fish_sim 调用者, I want 取得场景、画像、种子、策略及源码和导表身份, so that 我能准确说明本轮输入。
8. As a 调用者, I want 查看产物清单及文件是否存在, so that 我能区分未生成、已丢失与可读取的数据。
9. As a 调用者, I want 查看失败运行已留下的诊断和产物信息, so that 我能解释失败而不把它标为成功。
10. As a Agent 开发者, I want 使用版本化 JSON 响应和稳定错误码, so that 自动流程不依赖自然语言提示。
11. As a 模拟项目开发者, I want 查询引擎支持的指标目录, so that 我知道哪些分析可用以及需要哪些产物。
12. As a 数值策划, I want 查询指定画像的期末资源和公共进度指标, so that 我能复用现有 Generic 分析能力。
13. As a Fish 数值策划, I want 查询本段去重后的成长事件总数, so that 我能评估实际成长反馈数量。
14. As a Fish 数值策划, I want 查询各成长分类的每日和每周数量, so that 我能与目标规划对照。
15. As a Fish 数值策划, I want 新鱼种和新变异双标签保留且事件总数只计一次, so that 分类统计不会放大总成长量。
16. As a Fish 数值策划, I want 正常图鉴完成、新枪和新鱼池沿用现有首次口径, so that 接口与调优报告一致。
17. As a Fish 数值策划, I want 看到首次成长等待、相邻成长间隔和尾部等待, so that 我能识别在线成长空档。
18. As a Fish 数值策划, I want 查询关键节点的观察时间及在线时间, so that 我能区分日历节奏与实际游玩耗时。
19. As a 数值策划, I want 每个值标注单位、时间基准和统计范围, so that 我不会混淆自然日与在线时间或本段与生命周期。
20. As a 数值策划, I want 缺失和部分覆盖有明确原因, so that 我不会把未记录当成零或达标。
21. As a 数值策划, I want 真实零事件在完整覆盖窗口内仍返回零, so that 我能发现确实没有成长的日期。
22. As a fish_sim 调用者, I want 每项结论关联原始产物中的证据, so that 我能复核并向用户解释。
23. As a 数值策划, I want 旧运行仅使用保存的名称和身份, so that 当前生产表变化不会篡改历史解释。
24. As a 数值策划, I want 传入独立版本的目标规划, so that 同一运行可以对照不同规划而不改变游戏结果。
25. As a 数值策划, I want 为目标指定指标、画像、分类、期间和比较条件, so that 我能表达数量、节点和空档目标。
26. As a 数值策划, I want 目标对照返回目标、实际、偏差和判定, so that 我能确定主要偏离项。
27. As a 数值策划, I want 按明确权重和重叠规则计算刺激分, so that 刺激分与去重事件数分开解释。
28. As a 数值策划, I want 未知指标、单位不符和目标配置错误明确失败, so that 无效目标不会悄悄被忽略。
29. As a 数值策划, I want 尚未覆盖的目标日期显示不可评估, so that 截断或续跑结果不会被误判为零成长。
30. As a Agent 开发者, I want 命令成功与目标达标使用不同字段, so that 我能区分工具错误和数值不达标。
31. As a 数值策划, I want 导出可追溯的 JSON 与 Markdown 对照结果, so that 我能复用分析并交接结论。
32. As a 新模拟项目开发者, I want 在项目侧添加指标提供者, so that 不用重写运行查询与目标评估器。
33. As a 维护者, I want 用冻结产物贯通验证公共入口, so that 回归不依赖长模拟或本机生产数据。
34. As a 项目所有者, I want 分析不改动运行历史、源码、导表和目标源文件, so that 原有归因证据保持可复核。

## Implementation Decisions

### 统一调用边界

- 提供一个项目范围的分析服务作为上层入口，内部组合 RunQuery、指标提供者注册表及 TargetEvaluator。Python 调用与 CLI 共用它，不在命令分派层重新实现统计逻辑。
- CLI 提供 runs list、runs show、runs artifacts、metrics describe、metrics extract、targets evaluate 六项操作，支持结构化 JSON；描述与筛选参数使用显式选项，不执行任意表达式。
- 沿用现有 CommandResponse 外层语义：schema_version、command、ok、code、message、details、result。分析载荷另含自己的 schema_version 和指标定义版本，避免将某项指标口径变化等同于整个命令协议变化。
- 目标正常评估得到不达标，仍表示命令执行成功；判定放在 evaluation_status 和逐项目标结果中。参数错误、读取失败、身份冲突及无效目标使用结构化错误响应，沿用 CLI 既有退出码约定。
- P0 不新增 HTTP 或 MCP 服务，不要求 Dashboard 接入；新命令通过已有 CLI 暴露给 fish_sim。

### RunQuery：项目、历史与证据

- 复用 RunRegistry 的读写根和兼容读取规则，不另建运行数据库。支持显式历史根，默认使用项目既有历史布局；初始化查询不得触发 authoring 恢复、导表、就绪探测或模拟。
- list 接受 scenario_id、status、engine_id 和 kind 筛选，支持有上限的 limit 与 offset，返回匹配总量及是否还有结果。排序采用有效 started_at 降序，再以 run_id 稳定决胜；缺少有效时间的旧记录排在有时间记录之后，以 run_id 稳定排序，不声称该顺序代表真实时间。
- 默认列出 formal 运行；调用者可显式选择 smoke 或全部种类。新旧根同 ID 去重与写入根优先级沿用现有注册表，不以文件修改时间替换既有身份判断。
- get 返回 RunRecord 公共字段、可读取的 manifest、输入身份和覆盖窗口。场景、模型、引擎等同时出现在多个身份来源而互相矛盾时，显式报告冲突，不静默拼接成新的身份。
- artifacts 返回产物名称、角色、存在性和受项目边界约束的位置。manifest 声明的产物与注册表已知的报告、状态和开发诊断分别说明来源；旧运行无 manifest 时只列可验证项，并注明身份不完整，不推断缺失摘要。
- 不将任意用户字符串或 manifest 路径直接作为可读取文件；拒绝绝对产物名、越界相对路径和跨边界链接。发现异常时使用结构化诊断，保留已有安全目录读取约束。
- running、failed 运行可查询状态与产物清单；P0 的指标提取和目标评估要求登记状态为 success，防止使用正在写入或未完成的结果。报告生成失败但留有数据，不自动提升为成功或绕过限制。
- 一次提取/评估固定实际读取的状态、manifest、产物字节及其摘要，评估复用同一份已加载数据。输入在读取期间变化则拒绝结果；不以多个时点的数据拼出一份结果。只读分析不改写 run_status、执行耗时或原始 manifest。

### MetricProvider：发现、提取与统一语义

- 指标提供者通过 describe 和 extract 协议接入，按引擎 ID 显式注册。首批 Generic 与 fish_source，未知引擎保留运行查询能力，但提取返回不支持；不回退到 Generic 冒充支持。
- 指标描述至少包含稳定 metric_id、定义版本、名称、含义、值类型、单位、允许的维度/时间基准/统计范围、依赖产物、覆盖要求和聚合语义。新增指标不需要修改通用目标评估器。
- 每项指标结果包含 metric_id、profile_id、维度、value、value_status、coverage、time_basis、scope、reason 和 evidence。只在值可计算时提供 value；状态分为 recorded、not_recorded、not_reached、not_applicable。部分覆盖另以 coverage 表达，不把部分观测值冒充全量。
- not_reached 仅用于支持该语义的节点指标，表示完整观察区间内未见到该节点；不是所有空值的通用替代。未知指标或错误维度是输入错误，不返回 not_applicable 掩盖拼写错误。
- evidence 使用运行身份、产物名、JSON 定位符或稳定事件身份及内容摘要，必要时附观察时点。大集合可返回限定数量的示例证据及确定性选择条件、匹配总量与截断标记，不能静默截断统计输入。
- 金额、权重、刺激分和小数偏差使用精确十进制字符串；整数计数与秒数保留明确类型。运算精度按输入有效数字和运算范围设置，不能先经浮点或默认有限精度舍入再输出字符串。
- Generic 初始覆盖期末资源、首次解锁时间、购买次数、重生次数与回本时间，沿用其现有事件定义。对缺失文件、无该实体、没有发生事件和真实零值分别判断；不复制旧比较中缺失键默认零的行为。
- Fish Source 初始覆盖：本段去重成长事件数；按分类的成长标签数；每日/每周上述计数；首个成长等待、最长相邻成长间隔、尾部等待及三者最大值；按已记录成长身份查询节点时点。节点可返回墙钟与累计在线秒，查询者明确选择使用哪一种。
- Fish 成长集合覆盖现有报告分类，包括摸鱼厅、杠铃、神器、两类重生、突破资助、系统开放、正常图鉴、新枪、新鱼种、新变异与新鱼池。分类以提供者公开目录为准，不把中文展示名当作稳定键，不新增游戏奖励或成长规则。
- 复用现有 Fish 成长投影与首次去重逻辑；必要时抽出报告与指标共用的领域投影，避免两套实现。总数按成长事件身份去重，分类按标签计数；首次即变异可有两个标签但总数仍只加一，不合并同秒的独立成长事件。
- 保留新鱼池首次资格、图鉴完成与枪拥有分开、突破资助按成功支付计次、恢复历史不重放等既有规则。名称只来自运行保存的元数据，无可靠名称时保留 ID。
- 自然日按场景绝对秒除以 86400 后的第 1 日开始编号，周从第 1 日起每七日一组；这是模拟日而非运行机器的真实日期。分桶使用左闭右开区间，恰好边界归后桶；仅有边界事件不表示后桶已完整覆盖。
- 在线间隔使用累计在线时间差，排除离线时长。本段起始与末尾分别用于首次等待和尾部等待；没有成长但在线窗口完整时，整个本段在线时长是无成长等待；不足两个成长事件时，最长相邻间隔为 not_applicable，而不是虚构零。
- 本段事件汇总只覆盖 execution_window；生命周期指标必须有明确保存的累计事实或首次记录，不能用本段首条替代。缺失起始基线、在线区间或历史分类记录时，相关指标标明部分覆盖/未记录；不从状态采样插值补造事件。
- 成功但截断的运行允许分析。每日/每周统计给出实际覆盖区间；目标所需窗口未完整覆盖时不可判定达标。P0 不自动拼接多次续跑报告。

### TargetEvaluator：目标、权重与结果

- 接受显式提供的版本化 JSON 或 YAML 目标文件。平台不直接解析某个 Excel 布局；项目可在后续通过适配器把规划表转换成此协议。P0 交付一份可运行的 Fish 示例目标文件，值明确标注为演示，不把它登记为用户已确认的平衡目标。
- 目标集记录 target_set_id、version、来源说明及可选来源摘要；评估保存实际目标文件和规范化内容的摘要。规划表的名称/版本与游戏运行输入版本分别保存，不能混成一个模型摘要。
- 每条目标包含唯一 target_id、metric_id、画像、必要维度、单位、时间基准、scope、聚合方式、比较运算符和目标值。允许 eq、gte、lte 与闭区间 between；默认不设容差，可显式声明同单位的非负绝对容差。
- 每个选择器必须解析成一个明确值，或提供者声明支持的显式聚合。禁止隐式选第一个画像、默认相加全部成长类别或混合不同单位。多行目标逐项输出，不因某行缺数据而丢弃其他行。
- 支持按自然日/周的分类数量、截至指定日的累计数量、已支持节点的到达时间及在线空档上限。要求截至日的累计目标时，从第 1 日至截止日的证据必须完整，续跑本段不足以替代生命周期全量。
- 画像不一致、单位或时间基准不兼容、未知指标/分类、重复目标 ID、非法运算符、无效数字及不支持的聚合均是无效目标，整体返回可定位到 target_id 的配置错误，不静默跳过。
- 刺激分由显式选择的成长分类/事件集合及权重生成，与去重次数分列。必须声明计分方式：按标签加权时双标签分别贡献；按独立事件计分时每个选中事件只贡献显式给定的事件权重。两者不混用，也不自行推断工作簿作者对重叠的意图。权重使用非负精确小数，不设隐式默认权重。
- 目标评估逐项返回目标、实际、actual-minus-target 有符号偏差、判定、原因、覆盖情况及证据。区间目标分别返回相对上下界的偏差；缺失或未达到的节点不伪造数值偏差；真实零值正常比较。
- 逐项判定为 passed、failed、not_evaluable 或 not_applicable。完整观察已覆盖节点截止时间且节点仍未达到时，可将到达截止目标判 failed；窗口不足或生命周期证据缺失时为 not_evaluable。其他 not_reached 情况按指标和目标类型明确判断，不转为零。
- 总体状态优先级为 failed（至少一个确定不达标），其次 incomplete（没有确定失败但有不可评估），其次 passed（至少一个可评估目标且全部通过），全部不适用时为 not_applicable。失败与不可评估同时存在时保留两类数量和明细，不隐去覆盖不足。
- 目标文件至少包含一条目标；空目标集属于输入错误，不得空集通过。评估结果包含总数、各状态计数和有实际覆盖的目标数。
- 默认只返回响应；显式指定导出目录时生成 JSON 与 Markdown 对照表，包含运行身份、分析输入摘要、指标版本、目标版本/摘要、生成时间和逐项证据。目录必须位于运行与模型权威输入之外，不覆盖已有文件；冲突时明确失败，不能修改原始报告或目标源文件。
- 重复评估同一冻结运行与同一目标定义，除生成时间等明确元数据外应产生相同业务结果。更换目标可以改变判定，但必须清楚表明模拟结果没有改变。

### 兼容与维护

- P0 不改变现有 compare、gate 或旧扫描命令的行为；新指标使用独立版本协议。若共享领域投影需重构，旧报告的业务字段和统计口径保持一致。
- 不增加正式运行采样、checkpoint 字段或 Lua 操作。旧数据不足时返回覆盖缺口，不以新功能要求重新运行作为默认查询副作用。
- 实施时同步平台代码导航、命令文档和 fish_sim 的接口使用说明及代码导航；项目 README/RoadMap 仅更新受影响的已实现能力，不提前宣称规划已交付。
- 遵守执行工具包的独立分发与源码隔离决策。本次仅开发仓库交付，不自动构建、发布或推送 GameBalancer；既有打包依赖不得因共享投影意外引入 authoring 或开发诊断。

## Testing Decisions

- **已确认的主要验收边界**：项目分析服务及其 CLI JSON 入口。用户确认以冻结 Generic/Fish 运行产物贯通“查运行 → 提指标 → 对目标”，不依赖长模拟或当前生产表。服务集成测试承载业务矩阵，少量 CLI 测试验证参数、序列化、错误码和相同行为，不在每个私有转换函数重复测试。
- **外部行为优先**：以预先计算的事件数、时间、精确金额、目标判定及证据定位为断言，不能仅把另一份实现输出当成期望值。关键差分包含故意篡改事件/目标的负例，证明测试能发现错误。
- **既有先例**：运行注册表回归已覆盖新旧历史根、重复 ID、旧字段缺失与边界读取；命令行回归已覆盖稳定 JSON 响应和领域错误；Fish 报告回归已覆盖双标签单事件、旧续跑覆盖、同批观察、相邻在线边界及缺失不为零。复用其夹具与公开入口，不另建测试模拟器。
- **运行查询矩阵**：项目隔离、formal/smoke 筛选、稳定分页、同 ID 优先级、无时间旧记录、空历史、未知 ID、缺失/损坏 manifest、身份冲突、failed/running 查询与分析拒绝。验证目录链接和越界产物不被读取，读取期间输入变动明确失败。
- **Generic 指标矩阵**：多画像、期末资源、购买与解锁事件、重生、回本；完整零事件、缺失文件与不适用分开。包含超过 80 位系数、小数及正负偏差的精度案例。
- **Fish 指标矩阵**：首次变异双标签总数为一、同秒独立事件不合并、图鉴与新枪分计、重生/续跑不重复、初始池不计、冻结名称优先、缺失基线、部分自然日、日/周边界、相邻在线时段边界、离线排除、无成长与仅一个成长点的间隔定义。
- **目标矩阵**：四种比较运算、闭区间边界、显式容差、真实零、未达到但截止已覆盖、未覆盖截止、缺失数据、不适用、非法选择器、空目标集、重复 ID、画像/单位/口径不符；验证总体 passed/failed/incomplete/not_applicable 的优先级。
- **刺激分矩阵**：同一双标签事件分别按标签权重与事件权重计分，验证分数可不同但去重事件数恒定；未指定重叠规则应拒绝，未选择分类不得悄悄进入分数。
- **只读与归因**：记录运行历史、配置、导表和目标输入的字节与时间字段，分析后核对未改变；测试环境不具备游戏源码/Lua也能通过。验证不会调用模拟、导表或 status probe；导出只创建请求的分析产物，重复评估业务结果稳定。
- **报告兼容**：同一受控 Fish 产物经现有静态报告和新接口得到一致的成长身份及计数；如抽取共享投影，运行受影响的报告/收集/鱼池回归。无需改变模拟循环或强制新增真实 Lua 长程验证。
- **完成标准**：六项 CLI 操作、两类指标提供者、目标协议及 JSON/Markdown 导出均通过上述验收；文档说明能力和缺失边界，测试报告区分定向通过、既有失败和未运行范围。

## Out of Scope

- 跨运行可比性检查和新比较器；本次仅暴露输入身份并验证单次运行内部一致性。
- 多种子跑批、参数扫描、实验调度、统计置信区间和自动调参。
- 通用引擎能力协商、输入提供者重构、model watch 修复、截断或恢复协议扩展。
- 新的 ArtifactProvider/ReportProvider 插件体系、Dashboard 页面改版、HTTP/MCP 服务。
- 直接导入任意 Excel 布局、自动解析或修改 SettingValue 工作簿、生产改表与 Luban 导出。

- GameBalancer 构建、发布、提交或推送，以及 UE/DS 验证。
