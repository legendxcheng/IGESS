## 已核实游戏规则

- 游戏界面的“资源”对应现有材料余额，卖鱼和废料加工共用余额。
- 单卖与批卖都增加材料；批卖金额是逐鱼售价之和。
- 普通鱼售价为 `P0 × fishSellIncomeSeconds`，其中 `P0 = baseMoneyPerSecond × incomeMultiplier`；当前 `fishSellIncomeSeconds = 10`。
- 售价不包含鱼等级、重量、鱼厅倍率、重生倍率或画像收益倍率，不返还升级投入。基础产出为 2 的普通小白条，正常变异售出为 20 材料，1.5 倍变异为 30 材料。
- 币种变更没有修改售价公式。升级消费金币仍然有效，不回退至材料升级。
- 游戏只允许出售背包中的鱼（`hallSlot == 0`），上阵鱼和神兽拒卖。一键出售由玩家点击，出售全部可卖背包鱼，没有普通鱼品质、等级或通用锁定保护，也没有定时自动出售。

## 实现影响（调查结果，不是已完成工作）

1. 新增原子出售交易、出售策略与行为调度；区分游戏允许出售的对象和模拟玩家主动保留的对象。
2. 累计捕获数与当前库存数必须分开；现有投掷和恢复校验使用二者相等的假设。实例 ID 继续单调递增，不因出售回收。
3. 阵容和培养排名缓存必须支持删除。既有缓存主要处理追加和升级，删除上阵鱼或同长度替换都存在失效风险。
4. 先结算交易时刻以前的生产，再完成出售和后续阵容更新；验证完整与动作中恢复的等价性及失败原子性。
5. 完整与紧凑事件都保留出售数量、金额和材料余额；报告区分卖鱼材料与废料加工材料。当前累计材料产出只读取 `trash_material_added`，单改钱包会漏报收入。
6. 新收入可能改变鱼雷、鱼厅、境界和双 Luck 节奏。确定策略后再生成新正式基线，旧报告保留，不把规则与数据混合变化归因于单个字段。
7. 维护项目当前规则说明，修正 RoadMap 中“缺少出售价格公式”的过期阻塞说明；实施进度仍由 RoadMap 单独维护。

## 决策树

当前已知规则：出售入材料、一级产出定价、不退升级投入、既有金币升级有效。

首轮已确认（用户回答“全部按推荐”）：

- Q1 出售对象：模拟点击一键出售全部可卖背包鱼，还是额外保留高品质候补。
  - 确认：保护品质前 X 培养组，只出售组外且未上阵的普通鱼；X 沿用当前普通鱼名额定义。这是玩家选择，不是游戏出售限制。
  - 品质及排序沿用既有培养规则：一级产出含变异；同品质按等级降序、实例 ID 升序。上阵鱼即便不在前 X 也不出售。
- Q2 出售触发：固定整理、缺材料再卖或每次捕获后立即卖。
  - 确认：作为在线批量整理行为，每累计 5 分钟在线时间触发一次、耗时 3 秒；这是已确认的玩家画像假设，不是游戏配置事实。离线不出售。

第二轮已确认（用户回答“全部按推荐”）：

- Q3 额外留鱼：是否为未来扩容预留鱼，或为已有升级投入的落选鱼额外保留位置。
  - 确认：不增加保护条件。只保护当前上阵鱼与当前品质前 X；落选且未上阵的升级鱼也出售，不补偿升级金币。接受刚扩容时可能暂时缺鱼；容量实际增加后再按新 X 计算保留组。
- Q4 到期整理的调度顺序：是否打断当前动作，是否优先于已有重生与突破。
  - 确认：不打断进行中的动作；在下一决策点保留既有两类重生和可支付立即突破的优先级，之后到期出售优先于普通炸鱼、锻炼、升级和购买。卖后重新判断各系统的材料可支付条件，不为尚未到期的资金缺口提前出售。
- Q5 周期和下线边界：延迟执行、无可卖鱼或不足三秒时如何处理。
  - 确认：使用累计在线时间的 300 秒固定刻度；到期无可卖鱼则跳过、不耗时；有鱼但在线窗口不足三秒则顺延到下次上线。多次错过只合并成一次整理，不连续补卖；恢复存档不重置周期。

待整体确认的实现约束：出售开始时按当前状态确定整批实例并冻结，三秒结束时校验并原子提交；动作中恢复沿用既有已选动作机制，不重新抽选目标。两个现有画像采用相同出售规则，卖鱼不继承垃圾加工的画像倍率。沿用普通鱼支持范围、正式工作流和既有材料消费规则，验证完整账本、连续/分段等价及新基线。

## 完整调整方案

1. **出售规则**：新增批量出售普通背包鱼的原子命令，售价按实际游戏的一级产出乘出售倍率计算，当前倍率为 10；只增加材料，不返升级金币，不叠加垃圾加工、重生或画像倍率。上阵鱼、神兽及无效实例拒绝出售，不能由策略过滤替代命令合法性检查。
2. **玩家选择**：两个现有画像保护当前上阵鱼和全背包品质前 X 的普通鱼，出售其余普通鱼。前 X 沿用既有品质、同品质决胜与名额定义；不另留扩容储备，也不因历史升级投入永久保留落选鱼。
3. **时间与调度**：累计在线时间每 300 秒产生一次整理时机，批量出售占用三秒前台时间，期间后台生产正常结算。当前动作不被打断；重生、可执行立即突破仍在出售之前，出售在其余普通行为之前。空批次跳过；不足三秒顺延上线，错过周期合并一次，不因恢复存档重新计时。
4. **状态与恢复**：出售开始时冻结当批实例，完成时原子结算，失败不提交部分结果。累计捕获不回减、实例 ID 不回收，当前库存与累计出售数量保持守恒；排名缓存正确响应删除。checkpoint 保存周期与进行中出售，恢复不重卖、不漏卖。
5. **账本与报告**：完整和紧凑事件记录出售数量、来源金额及材料前后余额；材料收入分别展示卖鱼与废料加工，核对总收入和消费后的余额。卖鱼本身不计为永久进展，观察其引发的鱼厅扩容、鱼雷、境界、力量及双 Luck 变化。
6. **交付验证**：通过既有 IGESS 正式工作流生成 smoke、1d、7d、30d 新基线，记录生产输入、模型摘要、策略与画像。保留旧结果；同步 README、HANDOFF 与 RoadMap 当前规则，进度仍只记在 RoadMap。

## 验证重点

- 出售后继续投掷，库存守恒、累计捕获不变、实例身份单调递增；删除后新捕获即使数量恢复也不复用旧缓存。
- 一级产出定价包含变异、排除等级；升级过的落选鱼不获金币退款；卖鱼材料不乘废料加工倍率。
- 上阵保护与前 X 保护同时生效；品质相同的边界沿用已有决胜，扩容后用新 X 重新选组。
- 批次含上阵鱼、神兽、未知或重复实例等无效请求时失败原子性；空批次不占行为时间。
- 与重生、突破、普通行为同时可执行时的优先级，以及无提前出售、下线前不足三秒和跨日周期的行为。
- 出售动作中、到期等待中及离线中的 checkpoint 恢复与连续运行等价。
- 完整/紧凑事件、材料来源报表、最终钱包和存档一致；正式运行的必需产物和来源记录齐全。
