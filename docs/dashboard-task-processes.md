# Dashboard 任务执行与代码更新

开发 Dashboard 的模拟、分析和模型检查每次启动独立 Python 进程。更新模拟策略、适配器或报告生成代码后，下一次任务加载当前源码，不需要重启网页服务。首次安装此改造仍需重启一次旧服务。

## 执行链

`dashboard` 负责 HTTP 校验、项目隔离、任务准入、缓存状态及页面；`dashboard_tasks.DashboardTaskRunner` 负责进程启动、结果校验和失败归并；`dashboard_task_worker` 在新解释器中创建原有工作流，进入既有正式运行执行器。

模拟的输入准备、项目锁、引擎执行、checkpoint、产物、报告和持久化终态均留在工作流内。分析保留 `ok`／`needs_attention` 等原有状态。首次检查、手动刷新、任务完成后的检查走同一进程边界；轮询只读取缓存。

工作进程按源码文件启动，在导入 IGESS 前安装仅作用于 IGESS 模块的源码加载器，每次编译当前源码，避免短时间同尺寸修改仍命中旧字节码。第三方包使用正常导入方式。运行中的任务不主动热重载；这不是整个 Python 源码树在任意并发编辑下的原子快照。

## 结果与失败

每次任务使用独立临时目录及任务标识。请求、准备握手、运行归属和完成结果以 JSON 文件传递，完成文件原子替换；普通输出通过持续消费的管道读取，保留最多 64 KiB 尾部，不混入控制协议。有输出的任务将尾部与退出码保存到项目开发诊断目录，任务面板提供日志链接；通信异常的诊断也包含可获得的退出码及输出。日志写入失败单独提示，不覆盖已经保存的业务结果。

任务登记时记录运行目录身份。工作进程退出后，服务结合退出码、任务回执和注册表确认结果；异常只处理明确归属该任务的运行，不扫描并改写其他 `running` 记录。报告失败保留模拟产物。若终态已经保存而回传失败，保留保存的状态，并显示通信异常。启动／导入／通信失败产生任务级开发诊断；不会自动重试。

Windows 工作解释器在执行项目代码前等待服务许可。服务将实际解释器加入具有关闭即终止成员语义的 Job Object，再允许执行，避免虚拟环境启动器与真正计算进程不一致。任务退出或服务受控结束时回收其后代，包括 Lua 宿主。POSIX 使用独立进程组。模型计算本身不设固定墙钟超时；准备握手有有限等待时间。

## 保持的行为

- 同一项目的重复提交被拒绝，不同项目保留独立任务能力。
- 刷新网页、关闭标签页或切换项目不会取消后台任务。
- 有任务或模型检查时，服务重启仍被拒绝；历史清理沿用现有确认与互斥。
- 项目、配置、导表、运行目录与兼容历史读取规则保持原样。
- 历史列举、报告读取和历史清理继续使用原服务接口。
- 仅本机监听及 Host、Origin、CSRF 和报告路径校验不变。浏览器不能提交任意脚本命令。

## 仍需重启或重生成的情况

Dashboard 页面、路由、任务启动组件或不兼容的控制协议更新仍需重启服务，可使用 `Restart service…`。旧静态报告不会自动改变，需明确执行 `igess report` 重生成；缺失采集指标仍需要重新模拟。

执行工具包和调优工作台不使用本开发任务入口，也不因本次改造自动更新或发布。服务被操作系统强杀后的自动接管、自动重放和任意源码树原子冻结不在此机制的承诺内。

## 验证入口

真实进程验收位于 `tests/test_dashboard_task_processes.py`，覆盖同一服务内的代码与报告更新、旧字节码、模型检查刷新、进程崩溃、后代回收、导入失败修复、authoring、自定义历史根、跨项目并发、启动失败、回传异常及大量日志。旧 HTTP 路由测试使用明确注入的任务替身，不作为新代码加载的验收证据。

执行 `python -m pytest tests/test_dashboard_task_processes.py` 后，按范围补充 Dashboard、正式运行和历史清理回归。浏览器与实际 Fish/Lua smoke 的环境和结果应单独记录。
